# Dominicode Harness Init

Prepare a repository so an agent can work on it **and you can trust the result without reading every line**.

Part of the **Contract Review** system — Bezael Pérez · Dominicode.

## The mechanism in one sentence

```
Contract  ->  Harness  ->  Verdict
 (spec)     (harness)   (verification)
```

You sign a 40-line contract in advance. The harness keeps the agent on track. Verification delivers the verdict, not your patience while reading diffs.

This skill sets up **the harness**. Without a harness, the spec is a statement of intent and you have to issue the verdict manually — exactly the problem we came here to solve.

## Golden rule

**Never put a command in the harness that you have not run.**

A harness with invented commands is worse than having no harness: the agent thinks it is verified, you think it is verified, and nobody has checked it. Every command that ends up in the final file must have been run in Phase 1, with its output recorded.

If a command exists but fails in the repository as it is today, **that does not exclude it from the harness** — document it as a known red. An honest harness with two reds is worth more than a fake green one.

## PHASE 1 · Audit

Do not modify anything. Only read and run commands.

### 1. Identify the stack

Find manifests and derive the package manager from lockfiles, not convention:

| Manifest | Stack | Lockfile to check |
|---|---|---|
| `package.json` | Node/TS | `pnpm-lock.yaml`, `yarn.lock`, `package-lock.json`, `bun.lockb` |
| `pyproject.toml`, `requirements.txt` | Python | `uv.lock`, `poetry.lock` |
| `go.mod` | Go | — |
| `Cargo.toml` | Rust | `Cargo.lock` |
| `pom.xml`, `build.gradle` | Java/Kotlin | — |
| `*.csproj`, `*.sln` | .NET | — |
| `Gemfile` | Ruby | `Gemfile.lock` |
| `composer.json` | PHP | `composer.lock` |

If multiple manifests appear, this is a monorepo: ask which package the harness should cover before proceeding.

### 2. Inventory feedback mechanisms

Look for candidates in manifest scripts, `Makefile` / `Justfile` / `Taskfile`, and `.github/workflows` workflows — CI is often the most reliable source for the project's real commands.

The harness has six categories:

1. **Build / compilation** — does the project compile?
2. **Type checking** — do the types check out?
3. **Tests** — is behavior preserved?
4. **Lint / format** — is the style consistent?
5. **CI** — does this run automatically on every PR?
6. **E2E / smoke** — does the app start and respond?

### 3. Run each candidate

One at a time. For each one, record: exact command, exit code, duration, and the last lines of output if it fails.

A command that takes 8 minutes is not suitable for the short loop even if it works. The harness has two speeds:

- **Short loop** (under 60s): what the agent runs after every change.
- **Long loop**: what runs before opening the PR.

If a command does not exist, do not invent or install it yourself: report it as a gap.

### 4. Detect existing agent configuration

`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules/`, `.github/copilot-instructions.md`, `.claude/`.

If any already exist, **do not overwrite them**. Read them, then propose the diff in Phase 2.

### 5. Close the phase with the table

```
| Mechanism    | Command            | Status     | Time |
|--------------|--------------------|------------|--------|
| Build        | pnpm build         | OK         | 24s    |
| Type check   | pnpm tsc --noEmit  | OK         | 6s     |
| Tests        | —                  | DOES NOT EXIST  | —      |
| Lint         | pnpm lint          | FAILS (12) | 4s     |
| CI           | —                  | DOES NOT EXIST  | —      |
| E2E          | —                  | DOES NOT EXIST  | —      |
```

## PHASE 2 · Generation

Before writing anything, show the list of files you will create or modify and wait for confirmation. If a file already exists, show the proposed diff — never overwrite it without permission.

Generate using the **real commands verified in Phase 1**, never placeholders:

1. **`AGENTS.md`** — the repo's permanent contract: stack, verification commands at both speeds, conventions detected in existing code, and what the agent must not touch. Template at `templates/AGENTS.template.md`.
2. **`CLAUDE.md`** — if the user works with Claude Code and it does not exist, a one-line pointer to `AGENTS.md`. Do not duplicate the content: it will drift within two weeks.
3. **`.dominicode/spec.template.md`** — the task contract. Template at `templates/spec.template.md`.
4. **`.github/PULL_REQUEST_TEMPLATE.md`** — with an evidence checklist. Template at `templates/pr.template.md`.
5. **Minimal CI workflow** — only if there is no CI and the user asks for it. Run the long loop on every PR, nothing more.

## PHASE 3 · Report

Always close with this, in this format:

```
## Your harness status

**Current level: N of 4**

[Phase 1 table]

### Gaps, by impact
1. [Gap] — [what it currently lets through]
2. ...

### Your next move
[ONE concrete action, with the command or file]
```

### Levels

- **Level 0 — No harness.** There is no automated way to know whether the agent broke something. Every PR is reviewed manually, line by line.
- **Level 1 — It compiles.** Build or type check. Detects what crashes, not what silently degrades.
- **Level 2 — It behaves.** Tests and lint. The agent can iterate on its own until green.
- **Level 3 — Automatic.** The long loop runs on every PR without anyone having to remember to launch it.
- **Level 4 — With a verdict.** Acceptance criteria from the spec and agent review. You read the contract and verdict; inspect the diff only when the verdict is red.

One move per report. Anyone who tries to climb three levels at once climbs none.

## Strict rules

- **Do not invent commands.** It is stated above and is the most frequently broken rule.
- **Do not install dependencies** without asking. Auditing is read-only.
- **Do not write tests to get to green.** If tests are missing, it is a report gap, not a silent assignment.
- **Do not overwrite existing agent configuration.** Propose the diff.
- **Do not inflate the level.** If it is Level 0, say Level 0. This skill's value is knowing where you really stand; an inflated level returns the user to the original problem — believing they can trust something nobody has checked.
- **No emojis in generated files.** They will live in someone else's repo.

## Agents other than Claude Code

The system does not depend on Claude. For Codex, Cursor, Gemini CLI, or any agent with repository access, `references/generic-prompt.md` contains the same three phases as a standalone prompt that can be pasted and used.
